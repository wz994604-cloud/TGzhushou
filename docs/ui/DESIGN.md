# DESIGN

## 方向
现代 SaaS 控制台 × 专业运营工作台；浅色中性底、白色内容卡片、靛蓝主色与紫色品牌标记。

## 页面结构
1. `header`：活动中枢品牌、Telegram 发布工作台身份、北京时间。
2. `nav`：编写、任务、记录、设置四个稳定模块，当前项用主色填充。
3. 页面标题区：标题、说明、刷新/新建等上下文操作。
4. 内容区：编辑表单、任务卡片、记录列表、设置分组卡片。
5. 操作区：主操作与次操作有优先级，危险操作沿用红色文字。

## 视觉 tokens
- `--brand-primary: #4f46e5`
- `--brand-secondary: #7c3aed`
- 背景 `#f7f8fc`，卡片 `#fff`，边框使用低对比中性色。
- 12–16px 圆角；主要间距 8/12/16/24px。
- 标题 19–22px，区块标题 15–16px，正文 13–15px。

## 交互与状态
- 保留现有 API、事件绑定、草稿恢复、Telegram 表情键盘和任务状态逻辑。
- 为导航、卡片、列表、按钮提供 hover/active/disabled 视觉反馈。
- 保持空状态和错误状态文案靠近业务区块，不以装饰替代信息。

## 桌面与移动
- 桌面维持单列运营工作台，内容宽度 820px，避免低频信息抢占主任务。
- 移动端卡片缩小内边距，操作区固定但为内容保留底部空间；表单保持单列。

## 实施文件
- `index.html`：页面标题和主题色元数据。
- `src/main.js`：品牌 mark、产品名称和 header 结构。
- `src/style.css`：全局 token、品牌 mark、shell、卡片、状态和响应式样式。
- `README.md`：项目展示名称。

## 风险控制
- 不变更 API、数据库、Token、Telegram 发布行为。
- 不自动触发真实 Telegram 发送；部署前只做构建、测试和 healthz 验证。
