# UI_AUDIT

## 角色与主任务
管理员在 Telegram Mini App 中编辑并发布活动，需快速判断发布目标、任务状态和失败原因。

## 当前审计
- P0：无。现有发布和认证流程可用。
- P1：品牌 header、导航和内容卡片缺少统一的 SaaS 层级；主操作、当前模块和状态密度不够明确。
- P1：移动端固定操作区、窄屏间距与长标题需要更清晰的视觉边界。
- P1：任务与设置区需要统一 hover/selected/disabled 反馈，避免只有 toast 承载状态。
- P2：记录页可继续增加筛选和保存视图，但不在本次小范围改造中扩张数据行为。

## 信息架构
- Brand header -> 当前身份/时间 -> tab 导航 -> 页面标题/主操作 -> 卡片/列表 -> 状态提示。
- 继续使用编写、任务、记录、设置四个主模块，避免引入额外菜单。

## 视觉与组件
- 使用中性背景承载结构，靛蓝作为主操作色，紫色仅用于品牌标志。
- 圆角、边框、阴影统一；标题、区块标题、正文和辅助文案控制在四级。
- 卡片和任务列表增加 hover/selected 反馈；按钮维持 44px 触控高度。

## 状态矩阵
- Loading：保留页面 shell，按钮禁用并显示等待态。
- Empty：任务、目标、记录分别给出下一步文案。
- Error：toast 保持短反馈，设置和数据区增加区块级视觉边界。
- Disabled：目标无发布权限时保持禁用并展示原因。
- Selected：当前 tab、任务状态、可操作按钮有明确对比。

## 移动风险
- 固定底部 actions 不遮挡编辑器和 toast。
- 390px 宽度下标题、按钮、表单和抽屉不横向溢出。
- 对话框和表情键盘继续使用现有可视高度变量。

## 业务风险
- Token、Telegram init data、目标 ID 不写入视觉文档或截图。
- 发布、停止、删除和外链操作不改变后端确认边界。
