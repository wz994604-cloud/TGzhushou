# 飞机助手最终 UI 方案：Fluent Light / 克制玻璃运营工作台

版本：2026-10-05 · 待用户确认 · 身份：UI 设计师

## 一、最终结论

**最终推荐不是上一版的深色 SaaS 侧栏，也不是把现在所有区域继续玻璃化，而是：浅色 Windows 11 风格外壳 + 低饱和粉蓝氛围 + 清晰、不透明的业务内容 + Telegram 式列表与消息体验。**

保留桌面客户端质感，但让玻璃成为背景材质，而不是内容阅读的障碍。

我的上一版方案解决了层级，却偏向通用后台，品牌气质和桌面客户端感不足。本次修正这一点。对方方案的产品定位有价值，但把 Mica、Acrylic 和 Glassmorphism 混为一谈，并要求所有页面区域玻璃化，缺少可执行的材质分层、密度和状态规则。

因此不采用“50% / 30% / 20%”混合比例。设计比例不等于实现规范；最终以材质使用区域、控件尺寸、真实业务状态和验收条件为准。

## 三、对外部方案的取舍

| 外部建议 | 结论 | 最终处理 |
|---|---|---|
| Windows 11 客户端级工作台 | 采纳 | 通过排版、层级、面板、反馈建立客户端感 |
| Fluent / Mica | 有条件采纳 | 外壳模拟 Mica 观感，不把 Web 模糊称为原生 Mica |
| 粉蓝紫渐变 | 修正 | 只在底层保留极低饱和粉蓝，紫色限于很弱的过渡 |
| 顶部、侧栏、列表、消息区、资料区全部玻璃化 | 不采纳 | 内容区实底，浮层允许局部磨砂 |
| 保持三栏聊天 | 有条件采纳 | 宽屏且选中会话时可显示资料栏，其他情况收起 |
| 简洁、专业、长期使用舒服 | 采纳 | 清晰文字、稳定对比、减少空壳卡片和视觉噪声 |
| Glassmorphism dashboard 作为主要参考 | 降级 | 仅用于材质灵感，不作为业务布局与密度依据 |

### 关键纠正：Mica 不是满屏毛玻璃

微软将 Mica 定义为不透明的动态背景材质，建议作为应用底层，并明确不要在一个应用中重复施加背景材质。其价值是层次与聚焦，不是让所有列表与表单透出壁纸。[Microsoft Mica](https://learn.microsoft.com/en-us/windows/apps/design/style/mica)

Acrylic 才强调半透明纹理。微软建议用于临时浮层和部分辅助 UI；永久分区面板推荐不透明背景，并提醒并排、叠加 Acrylic 会产生视觉噪声和接缝，模糊渲染还有性能成本。[Microsoft Acrylic](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic)

**设计推论：本项目最合理的做法是“外壳有氛围、内容稳定、浮层有质感”。** 当前 Web 页面先实现这种视觉语言；原生窗口材质属于后续桌面容器工程议题，不由本次 UI 方案扩大到技术迁移。

## 四、截图审计：真正不理想的地方

| 观察区域 | 截图事实 | 影响 | 最终调整 |
|---|---|---|---|
| 左侧导航 | 粉紫蓝色带占据整个高侧栏，品牌白字落在浅粉底 | 装饰比业务强，品牌对比不足 | 浅灰蓝底、深色文字，轻微氛围只在底层 |
| 选中项 | 机器人块与聊天导航都使用深色大块 | 两个高权重焦点竞争 | 机器人中性选择器；导航浅蓝底 + 细主色标识 |
| 顶部栏 | 搜索和机器人选择占据大面积，多个灰色图标没有明显可用性 | 上下文重复，控件风格不统一 | 单一机器人入口；顶栏模块名、必要操作、账号 |
| 会话列表 | 顶部搜索、筛选、状态和整行启用按钮叠加 | 首屏可见会话数量下降 | 合并状态与启用操作，搜索仅保留一个 |
| 会话条目 | 辅助文字很小、时间接近边缘，滚动条明显 | 扫描费力，右侧对齐不稳 | 固定条目节奏、名字/摘要/时间栅格 |
| 消息区 | 无会话时仍有一条空渐变头部和巨大抽象圆形 | 空区看起来像尚未完成的模板 | 隐去无内容头部，紧凑居中空状态 |
| 资料区 | 无会话仍展示大资料面板、绿色“状态未接入”和蓝色发送按钮 | 状态含义冲突，操作像已可用 | 无会话关闭资料栏；未知状态中性色；发送入口回到会话 |
| 占位功能 | 标签、媒体等空卡片占据大块区域 | 页面被“未来功能”撑满 | 已选会话才显示资料；未开放项收成一行禁用说明 |
| 整体 | 多层浅底和卡片轮廓相似 | 材质多但层级少 | 只保留底层、内容层、浮层三层 |

截图只能说明看到的视觉与状态表达；“发送消息”在无会话时的实际行为未点击验证，本方案不推断其后端结果。

### 本地源码提供的实现线索

- 样式中存在多个主题段、重复聊天样式和后置 Web 覆盖规则；例如 src/style.css 的 2360、3030 附近分别出现主题相关段落。
- 后置 Web 规则使用高饱和渐变底、侧栏渐变以及外壳 blur；这说明局部追加覆盖可能造成主题难维护。
- 宽屏规则在 1280px 起默认展示资料栏，与截图空资料区的表现一致，但尚未证明线上就是同一版本。
- 页面结构中已有会话搜索、机器人选择、会话头部、编辑器和发布操作绑定，应尽量保留这些现有数据与事件关系。

开发交接要求：先确认最终生效的样式链，再整合本次主题；不要在文件末尾继续追加另一套竞争主题，也不要做无关的全项目格式化。

## 五、最终视觉系统

### 5.1 材质层级

| 层级 | 区域 | 规范 |
|---|---|---|
| L0 氛围底层 | 工作台底层 | 浅灰蓝底，两个静态低饱和粉蓝色斑；无动画、无强光晕 |
| L1 外壳 | 导航、顶栏 | 白色覆盖约 88–94%，保留极轻底色；不并排堆叠 blur |
| L2 业务内容 | 列表、消息、输入框、表格、表单 | 实底或接近实底；稳定文字对比，1px 边界 |
| L3 临时浮层 | 更多菜单、机器人下拉、资料抽屉、弹窗 | 允许单层局部 blur 12–16px，必须有纯色回退 |

这些透明度是设计起点，不是可读性保证。最终检查合成后的实际背景，文字不能因底色变化而变浅。

### 5.2 颜色与视觉 Token

```text
背景基础       #F3F5FA
粉色氛围       #F3E7EF（只用于底层，弱覆盖）
蓝色氛围       #E4EFFB（只用于底层，弱覆盖）
外壳回退       #F5F7FB
内容实底       #FFFFFF
消息画布       #F1F5F9
主文字         #1F2937
次文字         #5B6678
辅助文字       #697586
边界           #DCE3ED
主色           #0B63CE
主色 Hover     #0855B5
选中浅底       #E8F1FF
成功文字/底    #166534 / #ECFDF3
警告文字/底    #92400E / #FFFBEB
错误文字/底    #B91C1C / #FEF2F2
未知状态       #5B6678 / #EEF2F6
```

- 普通文字验收目标 ≥ 4.5:1；必要非文字控件边界与大字目标 ≥ 3:1，最终以实际合成色测量。
- 蓝色只用于主要动作、链接和选中状态；不能把所有辅助文字都变蓝。
- 默认浅色，不自动推出深色主题；深色模式后续单独设计。

### 5.3 排版与组件尺度

- 字体：Segoe UI Variable / Segoe UI / Microsoft YaHei UI / 系统 sans-serif 回退；中文不使用衬线风格。
- 页面标题 22px / 600；区块标题 16px / 600；正文 14px / 400；会话名 14px / 600；辅助 12px / 400。
- 行高：正文 1.5，列表摘要 1.4；禁止全站字号整体缩小来容纳内容。
- 间距：4 / 8 / 12 / 16 / 24 / 32px；普通页面 gutter 24px，聊天面板内部 16px。
- 圆角：输入/按钮 6px，内容卡 10px，弹层 12px；聊天分区不各自再套大圆角卡片。
- 按钮与输入：40px；移动触控目标至少 44px；图标 18–20px。
- 面板之间靠 1px 分隔线，不用厚阴影；浮层阴影参考 0 8px 24px rgba(31,41,55,.12)。
- 交互过渡 120–160ms，仅背景/颜色/轻微透明度变化；不使用持续光效。

## 六、桌面结构：客户端感来自工作区，而不是假窗口

浏览器里直接使用完整工作区，不画假的 Windows 关闭/最小化按钮，也不在网页中再嵌套一个带大边距的“桌面窗口”。真实桌面壳未来由桌面架构工程师决定。

### 默认结构

```text
┌──────────┬──────────────────────────────────────────────┐
│ 品牌     │ 模块名                         帮助 / 账号   │
│ 机器人   ├──────────────┬───────────────────────────────┤
│ 导航     │ 会话 / 搜索  │ 会话头部                      │
│          │ 状态提示     │                               │
│          │ 会话列表     │ 消息区             [资料可开] │
│          │              │                               │
│ 账号摘要 │              │ 编辑与发送                    │
└──────────┴──────────────┴───────────────────────────────┘
```

- 导航默认 216px；顶栏 56px。
- 聊天列表默认 320px，可在 300–340px 之间由架构方案定稿。
- 消息区最小目标 480px；资料栏 288–320px，不再默认占 400px 左右。
- 资料栏仅在已选会话且空间充足时展开；无会话默认关闭。
- 机器人切换只有一个权威入口，放导航顶部。聊天头部用文字提示当前机器人，不新增第二个选择器。
- 顶栏不提供虚假的全局搜索。现阶段会话搜索放在会话列表，其他模块使用自身真实支持的搜索/筛选。
- 暂未开放的通知、外观等不抢顶栏主位置；保留时必须 disabled 且有明确说明。

## 七、七个模块的最终规范

### 7.1 聊天：首个样板页

**未选择会话**

- 消息区只出现 48px 左右线性图标、标题“选择一个会话”、说明“从左侧查看历史消息”。
- 不显示空头像资料卡、未知在线状态、无对象发送按钮、空会话头部。
- 不画巨大圆球插画，不让空状态成为页面主角。

**会话列表**

- 标题、真实未读数、搜索、紧凑状态条；禁用筛选器仍标“即将开放”。
- 未启用收消息：单条中性或警示提示 + 紧凑启用入口；明确历史记录仍可查看，是否允许回复由真实状态决定。
- 行高 68–72px、头像 40px、名字单行省略、摘要单行省略、时间固定右对齐。
- 未读圆点/数字不挤压名字；当前会话浅蓝底 + 细蓝标识；hover 浅灰底。
- 时间采用一致的本地时间表达；完整时间放详情，不能把不同日的记录只显示时分造成误解。

**选中会话**

- 头部显示名称、类型/机器人上下文、资料开关；没有数据的在线状态不显示。
- 消息气泡左白右浅蓝，宽度不超过消息区约 70%，正文 14px；宽屏仍限制长段文本行宽。
- 编辑区实底、工具图标同规格，发送为唯一主色动作；发送中有等待态，失败提示保留在输入区附近。
- 资料栏只呈现真实返回的用户字段；标签、备注、媒体未开放时一行禁用说明，不制造空卡片。

### 7.2 编写活动

- 页面标题、保存状态、主编辑区、右侧 360px 预览；不套“玻璃大卡片包白卡片”的双层壳。
- 基本信息、消息内容与附件、跳转按钮、发布配置四段；名称输入和工具栏密度统一。
- 附件放在内容区，显示缩略图、类型、移除入口；本地预览明确标注不是最终 Telegram 实际渲染。
- 按钮行主显示文字/链接，颜色、行号、专属表情收入可展开高级项；现有功能全部可达。
- 保存草稿为次操作；发布动作根据实际模式标为“保存并立即发布”或“保存并启用定时”。不能合并成含糊的“保存并发布”。
- 群发保持独立危险影响说明与既有确认，不藏成看不清对象的普通发布动作。
- 底栏占自己布局行，正文预留空间；预览正文独立滚动，避免底栏压住长内容。

### 7.3 素材管理

- 本轮未重新逐页查看，以下为待对照现状的规范。
- 顶部上传主操作、真实类型筛选；现有搜索能力不足时不画可用搜索。
- 图片/视频使用统一比例缩略图，文件使用类型图标；卡片下方显示名称、类型和体积（仅真实字段）。
- 上传进度、失败重试、处理等待为独立状态；不为不存在的媒体能力新增接口。
- 多选动作仅在已有业务支持时展示，删除与普通选用分开。

### 7.4 联系人 / 用户

- 本轮未重新逐页查看，最终字段以现有接口为准。
- 使用紧凑表格；身份主列、真实可用状态、现有导入/筛选，不默认加入负责人、在线状态等字段。
- 批量选择显示数量与当前机器人范围；群发前回顾对象与消息，不把视觉整理变成默认发送。
- 长标识省略显示并提供完整查看，避免撑宽表格。

### 7.5 自动化任务

- 标题与真实筛选置顶，不为“好看”新增没有来源的 KPI。
- 状态、类型、下次执行、操作对齐；行高 64–72px，名称最多两行。
- 保留高频“编辑”入口；按当前状态提供一个适用次动作，其余放“更多”，不把每行所有按钮铺开。
- 草稿灰蓝、运行绿、暂停橙、停止灰；状态不能只靠颜色。
- 删除与停止在菜单中分组并保持既有确认；立即发布不得被视觉变成普通无影响按钮。

### 7.6 发布记录

- 本轮未重新逐页查看，以下为待对照现状的规范。
- 时间、目标、结果优先；错误摘要就地显示，完整详情通过抽屉查看。
- 失败红标、成功绿标，消息内容摘要中性；筛选只使用现有支持字段。
- 不自动新增“重试发送”；它可能造成重复发送，必须先有真实业务约束。

### 7.7 系统设置

- 分类宽 200–220px，表单阅读宽度 680–760px；对齐左侧网格，不在大玻璃板内漂浮。
- 分类是导航，不给每一项强阴影；表单分隔使用标题与细线。
- 机器人、目标、用户导入、管理账号按现有模块组织；Token、权限与当前机器人必须清楚区分。
- 输入字段实底；敏感值默认遮蔽；保存和机器人切换采用不同操作级别。
- 保存成功只根据真实响应显示，不能用纯前端动画假装成功。

## 八、组件与状态矩阵

| 状态 | 视觉 | 行为表达 |
|---|---|---|
| 默认 | 稳定实底与清晰文本 | 不用蓝色暗示所有文字可点 |
| hover | 轻微底色/边框变化 | 不大幅漂浮或发光 |
| selected | 浅蓝底 + 标识 + 字重 | 选中会话、导航、筛选需区分对象 |
| keyboard focus | 2px 主色焦点环 | 菜单、关闭、上传入口可通过键盘到达 |
| loading | 区块骨架或按钮等待 | 不遮住其他模块；发送避免重复点击 |
| empty | 原因 + 可用下一步 | 无会话、无记录、筛选无结果分别表达 |
| error | 就地红色摘要 + 真实可行操作 | 不依赖 toast；不自动重发消息 |
| disabled | 清晰可读的灰态 + 原因 | 即将开放、无权限、未选择对象分开 |
| unknown | 中性文字“未获取/未知” | 不显示绿色成功或在线徽标 |
| needs-review | 对象、数量、方式摘要 | 保留既有发送/删除/权限确认边界 |

## 九、响应式与长时间使用

以下宽度均指 CSS viewport，不是截图物理像素。精确滚动、布局实现由桌面架构工程师复核。

| 视口 | 设计行为 |
