# 飞机助手网页版 UI 精修方案

2026-10-06 · UI 设计师 · 待架构复核与用户确认交接

## 1. 唯一基准与本次目标

以用户最新提供的真实网页截图为基准：左侧导航、会话列表、已选会话消息区、右侧会话资料、底部输入区均保持当前结构与位置。

本次是当前网页精修，不是换设计语言、重做布局或把客户端效果搬到网页。此前生成的 Fluent / Glass 图片均属于探索稿，不作为开发视觉基准；旧方案归档在本文件同目录下的 web-ui-refinement/previous-exploration.md。

用户确认的目标：

1. 保留当前粉蓝背景，让面板颜色更轻、更透明。
2. 机器人区域取消深色底，名称文字用深灰黑，头像图片不换色。
3. 顶部独立机器人选择器撤出顶栏，切换入口整合到左侧头像＋名称区域。
4. 左侧功能文字、图标、行高适度增大，减少下方过度留空。
5. 文字、边界、按钮和状态微调；不改变三栏比例、聊天功能与权限。

## 2. 修改范围与不变项

### 本次修改

- Web 侧栏、顶栏、列表、资料面板与输入区的背景填充透明度。
- 左侧机器人入口样式与顶部切换入口整合。
- 导航尺寸、中文字体、文字颜色与字重。
- 当前选中、hover、focus、disabled、未知状态的表现。

### 保持不变

- 当前品牌、粉蓝背景方向、页面结构、三栏比例、模块顺序。
- 会话搜索、消息记录、工具栏、资料字段、草稿、发布与管理功能。
- 已有 API、权限、数据隔离、机器人切换后的上下文处理与异常回退。
- 未开放功能仍禁用，不添加示意图中的虚构能力。
- Mini App 与 Windows 客户端不纳入本次实现；只记录可复用视觉规则。

不新增光晕、巨大插画、假 Windows 窗口边框、彩色头像系统或独立的新主题。

若背景透出影响阅读，先提高对应阅读区白色填充，保留外层透光；不靠增加文字阴影补救。正文对比度目标 4.5:1，实际合成色与图片背景需测量，本方案没有将其描述为已经通过。

## 4. 左侧机器人入口

### 原因

当前头像区域与顶部下拉都表达当前机器人；头像块深色底过重，不符合用户要求。

### 规格

- 保留真实机器人头像，40px 圆形，不统一染黑。
- 名称 14px / 600、深灰黑；长名称单行省略，完整名称可通过已有提示机制查看。
- 区块高度 56px，内边距 10px 12px，头像和文字间距 10px。
- 浅色透明底、细边框、8px 圆角；取消当前深蓝填充和明显外阴影。
- 整个头像＋名称块作为可点击选择器，右侧 16px 下拉箭头。
- 展开列表使用真实已授权机器人；显示头像、名称、当前选择标识，不自动轮换“下一个”。
- 只有一个机器人时正常显示当前身份，按实际可选情况禁用展开或显示单项列表。
- 无机器人/无权限/加载失败分别表达真实原因。

### 实现边界

本地读取显示 #railBots 当前仅渲染选中机器人，而 #publisherSelect 使用 data.publishers 渲染完整选择列表。因此整合不等于隐藏顶部控件后直接沿用当前侧栏按钮：开发者须把完整选项呈现到侧栏入口，复用 switchPublisher 与既有切换流程。

优先评估把现有 select 迁移进头像区域的低改动方案；若采用弹层列表，仍复用同一数据和切换函数，不做两个不同状态源。先保证侧栏入口完全可用，再撤出顶部入口。保留切换中的等待、失败回退、权限与对象隔离，不新增接口。

键盘支持：Tab 到入口，Enter/Space 展开，方向键选择，Esc 关闭，关闭后焦点回入口。移动 Web 导航抽屉内仍能切换；本次不改 Mini App 的独立入口。

| 行高 | 常规高度窗口 54px |

| 分组标题 | 12px / 500，辅助文字色 |

保留模块顺序和名称。选中项使用浅蓝底＋3px 蓝色左标识，取消深蓝大块及发光阴影；hover 与 selected 要可区分。

低高度窗口按架构复核降为 46px 行高、12px 分组间距，仍保留 16px 字号和 22px 图标。导航内容必要时独立滚动，品牌/机器人/管理员区保持可达；不放大到把“系统设置”或管理员挤出视口。减少空白不是强行平均撑满全栏。

## 6. 文字精修

- 字体栈：Segoe UI / Microsoft YaHei UI / Microsoft YaHei / 系统 sans-serif。
- 表单、按钮、select、消息正文、资料值显式继承同一字体；检查出现衬线观感的字段，而非推断全站字体错误。
- 页/会话标题 20px / 600；资料区标题 16px / 600；正文与输入 14px / 400、行高 1.5；辅助说明与时间 12px。
- 品牌标题在浅粉背景上使用深灰黑；Logo 与头像原样保留。
- 资料区标签/值明确层级并保持对齐，长标识换行或省略后可查看，不改变字段来源。
- 不用全局 font-weight: bold，不为增强清晰度加文字发光或描边。

## 7. 聊天页局部规范

### 会话列表

保留搜索、筛选、收消息提示与会话行位置。降低面板底色遮蔽，文字更清晰；选中行沿用当前左蓝标识，底色统一为浅蓝透明填充。时间和未读数量保持对齐，真实统计不变。

### 消息区和输入区

保留当前日期、消息气泡、消息头部、工具栏、输入框与发送按钮的布局。气泡和输入区更凝实，聊天画布更透；不补造已读勾、在线状态或用户属性。

蓝色发送按钮保留，采用无发光的轻量表现；发送中/失败由实际状态驱动，不自动重发。工具图标保持当前功能和排序，不因效果图遗漏而删除。

### 资料区

保留当前资料布局、操作与卡片；本次不改成抽屉或重新压缩结构。只统一材质、字体、边框及阴影。

“状态未接入”用 #5F6B7A 文字和 rgba(95,107,122,0.08) 底，不用绿色。未选会话时发送入口禁用并说明需先选会话；已选会话是否可发送以真实权限与状态为准。未知资料不伪造成功或在线。

## 8. 状态与行为

| 状态 | 视觉与要求 |
|---|---|
| hover | 轻底色，无位移和光晕 |
| selected | 浅蓝底、蓝色标识、适当字重 |
| focus | 清晰 2px 蓝色外环，避免被容器裁掉 |
| disabled | 保留可读的灰文字，展示真实原因 |
| loading | 按钮等待反馈，防重复选择或发送 |
| error | 原因靠近对应操作，保留原内容 |
| unknown | 中性灰，“未接入/未获取”，与成功区分 |

未读、收藏、群组等未支持功能不因颜色修改变成可用。顶栏其他未开放图标维持禁用语义。

## 9. 其他模块继承方式

聊天样板通过前不批量调整其他页面。样板通过后：

- 活动：继承字体、玻璃面板、输入和按钮参数；不改编辑/预览比例、发布模式与操作含义。
- 素材：继承卡片边框和辅助文字；保留现有媒体与上传行为。
- 用户：继承表格文字、选中、筛选和禁用态；保持真实字段及机器人数据边界。
- 任务：继承状态颜色与操作按钮；不追加 KPI、重排高风险动作或变更执行状态。
- 记录：继承成功/失败/未知视觉与字段层级；不新增自动重发。
- 设置：继承表单规范；敏感字段、验证与权限不变。

所有页面调用同一 Token，不新增独立页面配色。Windows 客户端以后复用颜色、文字和组件规则，窗口材质/标题栏单独由架构确认。

| 主次动作 | 每个操作组一个明确主动作，其余次按钮/文字按钮；不同业务动作不可仅因统一颜色而合并 |
| 分组边界 | 优先细分隔线；只有独立任务需要卡片，不把每一字段变成卡片 |

半透明用于外层材质，输入和阅读区继续凝实；不对整页 opacity 降低，不重复叠加 blur。所有页面复用 Token 和组件类，不复制六份 CSS。断点、列宽和滚动由现有架构方案决定，本轮不另造断点体系。

## 17. 联系人 / 用户（players）

原因：名单、已选对象、私信记录应协调，但选择操作必须清楚，避免把取消选择理解成删除用户。

- 保留现有名单/已选分区和私信记录；不改成新CRM、不加标签、删除或伪造最近互动。
- 搜索、同步、CSV导入继承共用输入和次按钮；已选计数突出但不加大号KPI卡。
- 用户行头像40px，名称14px/500；ID/用户名及真实最近互动12px；复选框点击区清楚。选中用浅蓝底，与聊天会话行一致。

- 已选区人数、可滚动列表与返回编写入口保持原行为；滚动由当前架构负责，避免内容撑出页面。
- 私信记录复用发布记录的状态/时间样式，但保留原数据源。
- 验收：空名单、无搜索结果、无权限、长昵称、大量选择、导入错误可识别；机器人切换后名单和选择仍遵守现有隔离规则。

## 18. 自动化任务（tasks）

原因：状态与下一次执行时间应比装饰更醒目，不能为了统一视觉改变调度语义。

## 19. 发布记录（logs）

原因：记录用于核查结果，需要与任务、私信记录统一，不应以大面积状态底色掩盖失败详情。

## 23. 最终字体规范：中文高级感

用户确认：页面不使用英文装饰字体，整体采用中文字体体系，目标是干净、专业、高级，而不是花体或夸张艺术字。

### 字体原则

- 正文、导航、表单、按钮、资料字段和提示文字统一使用同一套中文无衬线字体。
- 页面标题、卡片标题和品牌标题不更换字体，只通过字重、字号、行高和字距建立层级。
- 同样的板块位置必须使用相同的字号、字重、行高和颜色；不要求全站所有文字只有一个字号。
- 不使用英文 Inter、Manrope、Sora 等字体，不混用中英文字体风格。
- 不使用花体、艺术字、描边字或发光字；高级感来自层级、留白、字距和玻璃材质配合。

### 字体栈

```css
font-family:
  "思源黑体",
  "Noto Sans SC",
  "Microsoft YaHei UI",
  "Microsoft YaHei",
  sans-serif;
```

如果项目未加载思源黑体 / Noto Sans SC，则使用系统回退，不在页面临时引入风格不一致的网络字体。开发者先确认实际字体加载与 computed style，再决定是否补充项目内字体资源。

### 文字层级

| 位置 | 字号 / 字重 | 行高 |
|---|---:|---:|
| 品牌标题 | 18px / 600 | 24px |
| 页面标题 | 20px / 600 | 28px |
| 卡片标题 | 16px / 600 | 24px |
| 字段标签 | 14px / 600 | 22px |
| 正文与输入 | 14px / 400 | 22px |
| 导航文字 | 15px / 500；选中600 | 22px |
| 辅助说明 | 12px / 400 | 18px |
| 时间、ID、状态 | 12px / 400 | 18px |
| 按钮文字 | 14px / 600 | 20px |

标题与品牌文字允许轻微增加字距（0.01em—0.02em）；正文和输入不增加明显字距，避免中文阅读松散。不要使用全局 `font-weight: bold`。

### 执行顺序

1. 先统一字体加载和基础文字 token。
2. 再按导航、页面标题、卡片标题、字段、正文、辅助信息分别修正字号与字重。
3. 对照编辑页、聊天页和设置页检查同位置一致性。
4. 在常规桌面、低高度和窄屏检查中文不截断、不溢出、不因字体变更挤压操作区。

本节覆盖前文涉及字体的泛化建议，是本轮前端执行的唯一字体规范。
